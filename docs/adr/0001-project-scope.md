# ADR-0001：项目范围与安全边界

- 状态：Accepted
- 日期：2026-09-23
- 决策者：tykhed666-lab

## Context

CryptoPilot 是一个面向 AI 应用开发工程师岗位的求职项目。

项目需要展示以下能力：

- Python 后端工程化
- FastAPI Web 服务
- 外部 API 与 WebSocket 接入
- RAG 知识检索
- LangChain 模型与工具集成
- LangGraph 有状态工作流
- 数据存储与缓存
- 自动化测试与 CI
- Agent 工具调用
- 交易系统的安全控制

币安生态同时提供公开行情、账户查询和订单接口。单纯制作行情查询工具，
不足以体现完整的 AI 应用工程能力；但让大模型直接控制真实账户，又存在不可接受的风险。

因此需要明确研究能力与交易能力之间的边界。

## Decision

### 1. 采用研究与交易双通道

系统划分为两个主要通道：

#### Research channel

研究通道负责：

- 获取公开市场行情
- 导入 PDF 和 Markdown 研究资料
- 执行混合 RAG 检索
- 调用搜索、行情和知识库工具
- 使用 LangGraph 编排研究流程
- 生成带来源的行业研究报告
- 给出条件式交易计划

研究通道不能直接创建真实订单。

#### Execution channel

执行通道负责：

- 读取经过验证的交易意图
- 查询账户和资产状态
- 进行确定性风险检查
- 支持模拟交易和 Spot Testnet
- 在人工批准后调用订单接口
- 保存订单请求、响应和审计记录

大模型只能提出交易意图，不能绕过执行通道直接调用真实下单接口。

### 2. 第一版只支持 Spot

第一版交易能力限定为币安现货。

原因：

- 现货不存在杠杆和强制平仓机制
- 订单模型比合约简单
- 风险范围更容易控制
- 更适合作为第一个完整求职项目
- 可以先验证签名、精度、余额和订单状态管理

以下能力暂不进入第一版：

- 永续合约
- 杠杆交易
- 期权
- 跟单
- 高频交易
- 自动套利

后续只有在现货测试网流程稳定并具备完整审计后，才评估增加合约功能。
