# CryptoPilot 第一周执行手册：项目地基与币安行情

> 周目标：从空目录做到一个可公开、可测试、可演示的币安现货行情后端。
> 开发目录：`E:\CryptoPilot`
> 工作量：Day 1–6 每天约 450–550 行有效变更；Day 7 只复盘和发布，不凑代码行数。
> 本周不使用真实账户、不配置交易权限、不调用任何下单接口。

## 1. 本周结束时必须得到什么

完成后，项目应当具备：

1. 一个规范的 Git/GitHub 仓库和 Python `src` 布局。
2. 四种运行模式的数据模型：`research_only`、`paper`、`spot_testnet`、`live_agentic`，默认且只能启动为 `research_only`。
3. `BinanceGateway` 端口和公开行情实现。
4. 可读取 `BTCUSDT` 的交易规则、24h ticker、K 线、深度和最佳买卖价。
5. 可持续接收 K 线、聚合成交和 book ticker WebSocket 事件。
6. EMA、RSI、ATR、点差和简化盘口失衡指标。
7. FastAPI 行情接口、Redis 缓存、健康检查和 OpenAPI 文档。
8. 离线可运行的单元/集成测试；GitHub CI 不访问币安网络。
9. `v0.1.0` Release 和一段 60–90 秒演示。

本周明确不做：

- LangChain、LangGraph、RAG、LLM Prompt。
- Binance Agent OS 授权。
- Testnet 或真实下单。
- MongoDB、Milvus、MinIO。
- 前端页面。

原因：这些都依赖稳定的领域模型和行情端口。本周先把确定性基础设施做对，后续 Agent 只调用工具，不直接处理交易所原始响应。

## 2. 本周关键技术决策

### 2.1 公开行情无需密钥

第一周优先使用币安 Market Data Only 服务：

```text
REST:      https://data-api.binance.vision
WebSocket: wss://data-stream.binance.vision:443
```

公开行情不需要 API Key。不要为了“提前准备”创建或填写主网交易密钥。

### 2.2 REST 第一周使用 httpx

第一周用 `httpx.AsyncClient` 封装公开行情，而不是让业务代码直接依赖自动生成 SDK：

- 更容易理解 HTTP、超时、重试和响应头。
- 更容易用 `MockTransport` 或 `respx` 离线测试。
- 业务层只依赖 `BinanceGateway`；后面仍可增加官方 `binance-sdk-spot` 执行适配器。

### 2.3 金额与指标的数据类型

- 价格、数量、手续费、余额：使用 `Decimal`。
- EMA、RSI、ATR 等统计计算：内部可以使用 `float`，API 输出前检查 `NaN/Inf`。
- 时间：统一保存带时区的 UTC `datetime`，前端再转换为本地时间。
- 交易对：内部统一大写且无分隔符，例如 `BTCUSDT`。

### 2.4 双通道只定义边界，不提前实盘

本周先定义以下端口，但只实现 `PublicMarketProvider`：

```text
BinanceGateway
├── MarketDataProvider       本周实现
├── AccountProvider          后续 Agent OS MCP 实现
└── ExecutionProvider        后续 Paper/Testnet/Agent OS 实现
```

## 7. Day 3：BinanceGateway 与异步 REST 客户端

### 学习目标

- Python async/await、连接池、超时和上下文管理。

- Adapter/Port、DTO mapper 和依赖倒置。

### 当天任务

1. 定义 `MarketDataProvider` Protocol，不暴露 httpx 类型。
2. 创建 `BinancePublicRestClient`，复用一个 `httpx.AsyncClient`。
3. 实现：
   - `ping()`
   - `get_server_time()`
   - `get_symbol_info(symbol)`
   - `get_klines(symbol, interval, limit)`
   - `get_ticker_24h(symbol)`
   - `get_book_ticker(symbol)`
   - `get_depth(symbol, limit=20)`
4. 将交易所原始 JSON 映射到领域模型。
5. 采集请求耗时、HTTP 状态和已用权重响应头。
6. 对 GET 请求实现有限重试：网络错误、429、部分 5xx。
7. 429 优先遵守 `Retry-After`；重试次数用尽后抛领域异常。
8. 创建 Fake provider 和录制后脱敏的 JSON fixture。

### 重试边界

- 4xx 参数错误不重试。
- 429 按 `Retry-After` 等待，并设置最大等待上限。
- 5xx 使用带 jitter 的指数退避。
- 每次调用有总 deadline，不能每次重试都重置无限时间。
- 第一周只有只读 GET；后续订单 POST 绝不能复用“盲目重试”策略。

## 14. 本周最容易踩的坑

1. 为追求 500 行制造大类和重复 DTO。
2. 将币安原始 dict 直接传入业务层。
3. 每个请求新建 `AsyncClient`，失去连接池。
4. 429 后立即重试，造成 IP ban 风险。
5. WebSocket 断线后无限快速重连。
6. 用 `float` 保存订单价格和余额。
7. 测试依赖实时币安网络，导致 CI 不稳定。
8. 在第一周提前实现下单、LLM 或完整 order book。
9. 将 `.env`、日志、行情大文件提交 Git。
10. 只测试 happy path，没有超时、断线和错误 JSON。
